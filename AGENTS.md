# Calma WorkSpace

Room-booking web app for a shared study/work center, built in 3 Scrum sprints. Spec: `Calma-WorkSpace-Scrum-Project.md`. Product Backlog: `backlog.md`. Team process: `docs/WORKFLOW.md`.

Two developers work in parallel on this repo, one with Claude Code and one with Codex. Your teammate's agent is changing the same codebase right now, so keep to your story's scope and treat shared contracts as shared (see Rules).

## Domain

Keep these French terms as the names in code, routes, and UI. They match the backlog and Jira.

- **Salle**: a room. Has a capacity, a type, and equipment. The gérant configures it.
- **Créneau**: a time slot (date, start, end).
- **Réservation**: a salle booked for a créneau by a client. It has a *nature*: étude personnelle, tâche personnelle, réunion, or formation de groupe. It is either individual or a group booking with a number of people.
- **Temps tampon**: the minimum gap between two réservations of the same salle.
- **Tarif**: an hourly or daily price.
- **Actors**: client (profil: étudiant, élève, développeur, entrepreneur), gérant (manager), agent de suivi (front desk, daily planning), agent de paiement (records payments, issues reçus).

Numeric rules (opening hours, slot granularity, min/max duration, temps tampon, booking horizon) and the nature ↔ salle-type compatibility table live in `backlog.md` → *Paramètres du centre*. Read them from there; define each value once in `src/domain/` and import it everywhere.

## Stack and commands

TanStack Start (React 19) + TypeScript strict, shadcn/ui + Tailwind v4, react-hook-form + zod, TanStack Query, Drizzle + PostgreSQL, Better Auth, Jest, Biome. Reasons: `docs/adr/001-stack.md`.

```bash
pnpm install
cp .env.example .env.local   # then set BETTER_AUTH_SECRET
pnpm db:up                   # Postgres 17 in Docker, host port 5433
pnpm db:migrate
pnpm dev
pnpm test                    # Jest
pnpm check:fix && pnpm typecheck
pnpm db:generate             # after editing src/db/schema.ts; commit the drizzle/ output
pnpm dlx shadcn@latest add <component>
```

Conventions:

- **Tests are Jest**, the course requires it. Vitest is the Vite default; use Jest anyway. Component tests start with `/** @jest-environment jsdom */`.
- **Business rules are pure functions in `src/domain/`** (availability, overlap, capacity, durée, tampon, prix), unit-tested without the framework or database. Server functions and routes call them.
- **Forms**: one zod schema per form, shared by the react-hook-form resolver and the server function that receives the data, so the server re-validates every field. Render fields with shadcn `Field` components.
- **UI text is French.**
- `src/components/ui/` is generated by shadcn; add to it with the CLI rather than by hand.

## Working a story

The branch name carries the Jira key (`SCRUM-9-reservation-form`). Each step ends on its completion criterion.

1. **Read the story.** Fetch the Jira issue for the branch's key from project `SCRUM` on `medjmalami.atlassian.net` (Atlassian MCP if configured, otherwise ask the human to paste it). Done when you can list every acceptance criterion. If a criterion is missing or ambiguous, stop and ask: the Product Owner owns acceptance criteria.
2. **Red.** Write one failing test per acceptance criterion, named after the criterion. Done when each new test runs and fails for the expected reason.
3. **Green.** Implement until those tests pass. Done when the full suite and the linter pass.
4. **Hand off.** Fill `.github/pull_request_template.md`: map each acceptance criterion to the test that proves it, and list anything out of scope you noticed as a candidate Jira ticket.

## Reviewing a teammate's PR

You are the first-pass reviewer for code the other agent wrote. Check every acceptance criterion of the linked Jira story against the diff and the tests, then every item of the Definition of Done. Report findings ranked by severity, each with the file and line and a concrete failure scenario. The human reviewer decides what to act on.

## Rules

- **Scope**: change only what the current story needs. Unrelated fixes go in the PR description as candidate tickets.
- **Commits**: `SCRUM-<n> <imperative summary>`. The key links the commit to the Jira issue.
- **Shared contracts**: the data model, migrations, and API routes are documented in `docs/architecture.md`. Changing one means updating that file in the same PR and flagging it at the top of the PR description, because the other developer builds against it.
- **Decisions**: a technical choice someone might question later (library, structure, pricing rule) goes in `docs/adr/NNN-title.md` as context / decision / consequences. These feed the report's "technical choices" section.

## Definition of Done

From the course spec. A story is Done only when all four hold:

1. its code has been reviewed and approved by the other team member;
2. its tests pass in CI;
3. its acceptance criteria were validated by the Product Owner on the test environment;
4. it runs in the test environment.

The **test environment** is a local run of `main` from a clean checkout (`pnpm install && pnpm db:up && pnpm db:migrate && pnpm build && pnpm preview`) plus a green GitHub Actions run. There is no hosted deployment.
